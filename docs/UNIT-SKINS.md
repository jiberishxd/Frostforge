# Independent portrait and unit-frame artwork

Build 0.8.6 draws all 42 approved shells over their native health and power bars, with independent width, height and positioning controls. No additional edge strips or shadows are drawn. A solid near-black backing fills the power opening only when there is no visible native power bar. Visible power bars use their own backdrop, so JUI cannot cover a live resource fill. The image assets are unchanged. Shared stone fills, selectable texture ownership, and the EllesmereUI 9.2.9 adapter remain available. In `/jui`, select Player, Target or Focus. **Portrait art** controls only the decorative portrait surround. **Unit-frame art** controls the separate sculpted shell. The Advanced page selects health/power texture ownership. Both settings are independent per unit; either, both, or neither may be enabled. The portrait itself stays under its provider’s control. Existing `unitStyle=FULL` settings migrate to `unitFrameShown=true` without changing portrait visibility. The default is portrait art on and unit-frame artwork off.

The full skin combines a substantial sculpted shell with plain stone health and painted power materials. All 42 class/race/faction identities have original shells inspired by their existing portraits and the Warcraft identity references recorded in the artwork provenance. All identities share one original full-bleed, grayscale stone health material, with no ornamental markings; the provider supplies its color. Existing identity-specific power materials are unchanged. Blizzard's health/reaction and mana/rage/energy hues remain native. There are no new portrait or level-badge circles.

Every source is uniformly contained in a transparent 512 × 256 atlas. The fitter records each painting’s actual health/power openings. It does not erase a rectangular name corridor, warp shoulders or force the divider into a four-pixel band. Thirteen decorative sections register to the two actual bars. The existing power bar is aligned below health, with width, height and gap derived from those openings. At a 20-unit health height, the Priest separator is about 6.6 UI units, matching the source ratio. Endcap proportions follow health height and effective scale; center spans follow bar width. The lower ornament hangs below power. Target/Focus mirror the artwork. Portrait sliders remain independent. Native bar layouts outside the pinned baselines require in-game fitting checks.

Blizzard, ElvUI or Ellesmere keeps the StatusBars, values, fill direction, masks, predictions, labels, resources and secure clicks. When JiberishUI manages fills, it changes the existing fill region's texture/UVs and the power bar’s presentation geometry. On Blizzard it snapshots the power bar’s points and size first; health geometry is unchanged. ElvUI/Ellesmere fitting snapshots both bars and preserves their combined outer stack height. Two addon-owned, mouse-transparent shell halves follow the bars, use independent unit-frame strata plus the configured level/draw layer, and draw above their owning bars (Automatic also follows the provider root). Higher settings and extreme fitting can cover native labels. No secure object is reparented or replaced. Turning off unit-frame artwork restores its managed fill appearance and power geometry; the separate stock-wide stone toggle (on by default) can keep Blizzard bars textured without shells; hiding portrait artwork has no effect on the bars; texture redraws update the restoration record. New attachment, power fitting/restoration, fill changes/restoration and shell reconfiguration wait until combat ends. The latest queued setting wins.

**Unit-frame provider** independently selects AUTO, BLIZZARD, ELVUI or ELLESMERE. AUTO prefers visible `ElvUF_Player/Target/Focus`, then `EllesmereUIUnitFrames_Player/Target/Focus`, using their public `Health`/`Power` members; otherwise it uses Blizzard bars. Hidden provider roots can be prepared when Blizzard is hidden. An explicit provider waits for its own frames. Blinkii or another portrait provider can coexist with either suite’s bar artwork.

For ElvUI/Ellesmere, both bars must be horizontal, attached to the same container, aligned, and power must sit below health. The fitter preserves the original stack height while dividing it into source-proportional health, separator and power heights. It snapshots and restores both bar layouts, leaving the root, clipping container, parent relationships and provider settings untouched. A provider redraw becomes the new baseline; theme switches do not accumulate shrinkage. Detached, above-health or vertical power layouts retain their geometry and receive available fill textures only in JIBERISH mode, with a diagnostic explanation. Automatic shell layering follows the provider root and is always at least one level above the owning bar. Default portrait layering follows just below the portrait backdrop. Higher explicit shell strata/levels take precedence; lower saved choices cannot put the shell behind the fill.

ElvUI additionally requires full-width attached power: its inset, mini/spaced, offset and detached settings are excluded. Its opposing health anchors are temporarily replaced with the same top-left position so the fitted height can take effect; the complete original anchor set is restored on disable. Provider redraws and parent resizing are remeasured. Rounded fitted readback does not accumulate or trigger repeated writes.

These provider layout rules differ from the Blizzard power-only fitting described above. Both share the same unmodified artwork and texture restoration/combat gates.

Commands:

```text
/jf set playerFrame unitFrameSource ELLESMERE
/jf set playerFrame unitFrameShown on
/jf set targetFrame unitFrameShown on
/jf set focusFrame unitFrameShown on
/jf set playerFrame shown off
/jf set playerFrame unitFrameShown off
```

Blizzard source paths are verified against the Retail and Forever revisions in `phase1-sources.json`. Retail Player uses PlayerFrameContent.PlayerFrameContentMain.HealthBarsContainer.HealthBar and ManaBarArea.ManaBar. Target/Focus use TargetFrameContent.TargetFrameContentMain.HealthBarsContainer.HealthBar and ManaBar. Forever first follows `healthbar` and `manabar`, which its `UnitFrame_Initialize` binds to the active native bars. Verified Mainline child paths remain a fallback before those bindings exist. Every inspected frame must be present and non-forbidden. Shell layout requires only public bar geometry. Unreadable or unrestorable fill metadata retains the native fill while leaving the shell visible; metadata is retried without reading health/power values. `/jui status` reports requested and resolved portrait sources, each toggle, and detailed shell/fill status. The options window shows a compact provider summary.

Offline checks cover restoration, native redraws, combat queuing, hidden/replaced/forbidden bars, source-proportional fitting, power geometry restoration, source changes, settings and frame/hook reuse. They cannot certify WoW's secure engine. Live tests must cover resource changes, combat, vehicles, prediction overlays, target/focus switching and turning the mode off on both clients. The standalone fitting comparison is in `artwork/unit-frames/index.html`.

Recognized NPC city affiliations reuse the corresponding existing race shell and portrait through one resolver. This applies in automatic modes; fixed artwork remains authoritative. See [city mappings and fallback limits](NPC-CITIES.md).

## Shared texture and fill ownership

`JiberishUI Stone` registers as a `statusbar` in an installed LibSharedMedia-3.0. Registration retries when addons load and at login, so consumers may load before or after JiberishUI. No library is bundled, no provider settings are edited, and no artwork toggle is required to use the shared texture. It reuses the existing Paladin health TGA; every health variant has identical grayscale stone pixels.

Each unit's `unitFrameFill` selects `AUTO` (default: Jiberish fills on Blizzard, provider fills on ElvUI/Ellesmere), `PROVIDER` (keep provider fills), or `JIBERISH` (explicitly apply our health/power textures). The shell remains independent. In provider mode, JiberishUI performs no fill writes or new texture hooks. Switching away from Jiberish mode restores captured appearance outside combat; later provider texture selections take priority, including when the user selects our shared Stone asset. Existing observer hooks become inactive. UV-only redraws still restore the prior atlas correctly. Profiles/backups retain this per-unit setting.

See [setup instructions](SETTINGS.md). SharedMedia remains available independently of all artwork toggles.

## Original shell overlap and independent fitting

The original shell is drawn once above the native health and power bars. Its transparent opening cells retain the existing curved corners and bevels. The measured horizontal opening sits one health-bar UI unit inside each bar edge at 100%, so the actual artwork overlaps the fill. There are no copied inner rails, extra shadows or additional borders. All image files remain unchanged.

In **Unit frame**, reduce **Artwork width (%)** to move the original sides inward. **Artwork height (%)** scales both halves around the shared health/power-stack center, keeping the joining divider continuous. Both percentages range from 75–150 with a default of 100. **Artwork horizontal offset** and **Artwork vertical offset** move the shell independently of portraits and native bars, from −512 to 512 UI units. Positive X moves right; positive Y moves up. Extreme adjustments can cover native labels or reveal the bar outside the shell; use Reset unit-frame fitting to return to 100%/100% and zero offsets.

The shell's strata and level cannot fall below the owning bar. Automatic also follows the provider's root layer; higher explicit strata remain available in Advanced. Older Background / level-zero profiles therefore still place the actual artwork over the fill. Legacy `unitFrameInset` values remain valid for backup import compatibility but have no visual effect and no settings control.

Fitting controls change only artwork dimensions and position. Existing provider fitting still reserves source-proportional separator space. Native values remain provider-controlled. Optional Blizzard color and texture choices apply separately; Automatic retains ElvUI/Ellesmere fill ownership. Edits defer during combat; shell regions are reused and follow native visibility. Portrait and cast-border controls remain independent.
