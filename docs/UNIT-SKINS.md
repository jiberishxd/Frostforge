# Independent portrait and unit-frame artwork

Build 0.7.5 adds painted inset edges and independent artwork width/height controls to all 42 themes. Shared stone fills and selectable texture ownership from 0.7.4 remain available. The Shaman shell now integrates a balanced elemental mask, carved wood/stone totems, rope and beads without the red banners or oversized tusks. The EllesmereUI 9.2.9 bar adapter remains supported. The existing build exports all 42 source shells without squeezing their dividers or cutting their upper shoulders. Paladin restores the official class-inspired crowned lion inside its flared-wing endcap. The 126 portrait, hub and minimap textures remain unchanged. In `/jui`, select Player, Target or Focus. **Portrait art** controls only the decorative portrait surround. **Unit-frame art** controls the separate sculpted shell. The Advanced page selects health/power texture ownership. Both settings are independent per unit; either, both, or neither may be enabled. The portrait itself stays under its provider’s control. Existing `unitStyle=FULL` settings migrate to `unitFrameShown=true` without changing portrait visibility. The default is portrait art on and unit-frame artwork off.

The full skin combines a substantial sculpted shell with plain stone health and painted power materials. All 42 class/race/faction identities have original shells inspired by their existing portraits and the Warcraft identity references recorded in the artwork provenance. All identities share one original full-bleed, grayscale stone health material, with no ornamental markings; the provider supplies its color. Existing identity-specific power materials are unchanged. Blizzard's health/reaction and mana/rage/energy hues remain native. There are no new portrait or level-badge circles.

Every source is uniformly contained in a transparent 512 × 256 atlas. The fitter records each painting’s actual health/power openings. It does not erase a rectangular name corridor, warp shoulders or force the divider into a four-pixel band. Thirteen decorative sections register to the two actual bars. The existing power bar is aligned below health, with width, height and gap derived from those openings. At a 20-unit health height, the Priest separator is about 6.6 UI units, matching the source ratio. Endcap proportions follow health height and effective scale; center spans follow bar width. The lower ornament hangs below power. Target/Focus mirror the artwork. Portrait sliders remain independent. Native bar layouts outside the pinned baselines require in-game fitting checks.

Blizzard or Ellesmere keeps the StatusBars, values, fill direction, masks, predictions, labels, resources and secure clicks. When JiberishUI manages fills, it changes the existing fill region's texture/UVs and the power bar’s presentation geometry. It snapshots the power bar’s points and size first; health geometry is unchanged. Two addon-owned, mouse-transparent shell halves follow the bars, use the unit's configured strata/level/draw layer, and default to BACKGROUND behind native controls. Raising these settings may cover native UI. No secure object is reparented or replaced. Turning off unit-frame artwork or resetting the component restores captured native appearance and power geometry; hiding portrait artwork has no effect on the bars; texture redraws update the restoration record. New attachment, power fitting/restoration, fill changes/restoration and shell reconfiguration wait until combat ends. The latest queued setting wins.

**Unit-frame provider** independently selects AUTO, BLIZZARD or ELLESMERE. AUTO uses the active `EllesmereUIUnitFrames_Player/Target/Focus` objects and their `Health`/`Power` members when available, otherwise the client’s Blizzard bars. An explicit Ellesmere choice waits for its frames. Blinkii or another portrait provider can coexist with Ellesmere bar artwork. ElvUI bar styling remains outside this adapter.

For Ellesmere, both bars must be horizontal, attached to the same container, aligned, and power must sit below health. The fitter preserves the original stack height while dividing it into source-proportional health, separator and power heights. It snapshots and restores both bar layouts, leaving the root, clipping container, parent relationships and provider settings untouched. A provider redraw becomes the new baseline; theme switches do not accumulate shrinkage. Detached, above-health, hidden or vertical power layouts retain their geometry and receive available fill textures only in JIBERISH mode, with a diagnostic explanation. Default shell layering follows the Ellesmere panel level plus one, beneath the bars. Default portrait layering follows just below the portrait backdrop. Explicit saved strata/level settings take precedence.

These Ellesmere layout rules differ from the Blizzard power-only fitting described above. Both share the same unmodified artwork and texture restoration/combat gates.

Commands:

```text
/jf set playerFrame unitFrameSource ELLESMERE
/jf set playerFrame unitFrameShown on
/jf set targetFrame unitFrameShown on
/jf set focusFrame unitFrameShown on
/jf set playerFrame shown off
/jf set playerFrame unitFrameShown off
```

Blizzard source paths are verified against the Retail and Forever revisions in `phase1-sources.json`. Retail Player uses PlayerFrameContent.PlayerFrameContentMain.HealthBarsContainer.HealthBar and ManaBarArea.ManaBar. Target/Focus use TargetFrameContent.TargetFrameContentMain.HealthBarsContainer.HealthBar and ManaBar. Forever first follows `healthbar` and `manabar`, which its `UnitFrame_Initialize` binds to the active native bars. Verified Mainline child paths remain a fallback before those bindings exist. Every inspected frame must be present and non-forbidden. Shell layout requires only public bar geometry. Unreadable or unrestorable fill metadata retains the native fill while leaving the shell visible; metadata is retried without reading health/power values. `/jui status` reports requested and resolved portrait sources, each toggle, and detailed shell/fill status. The options window shows a compact provider summary.

Offline checks cover restoration, native redraws, combat queuing, hidden/replaced/forbidden bars, source-proportional fitting, power geometry restoration, source changes, settings and frame/hook reuse. They cannot certify WoW's secure engine. Live tests must cover resource changes, combat, vehicles, prediction overlays, target/focus switching and turning the mode off on both clients. The standalone fitting comparison is in `artwork/unit-frames/index.html`.

Recognized NPC city affiliations reuse the corresponding existing race shell and portrait through one resolver. This applies in automatic modes; fixed artwork remains authoritative. See [city mappings and fallback limits](NPC-CITIES.md).

## Shared texture and fill ownership

`JiberishUI Stone` registers as a `statusbar` in an installed LibSharedMedia-3.0. Registration retries when addons load and at login, so consumers may load before or after JiberishUI. No library is bundled, no provider settings are edited, and no artwork toggle is required to use the shared texture. It reuses the existing Paladin health TGA; every health variant has identical grayscale stone pixels.

Each unit's `unitFrameFill` selects `AUTO` (default: Jiberish fills on Blizzard, provider fills on Ellesmere), `PROVIDER` (keep provider fills), or `JIBERISH` (explicitly apply our health/power textures). The shell remains independent. In provider mode, JiberishUI performs no fill writes or new texture hooks. Switching away from Jiberish mode restores captured appearance outside combat; later provider texture selections take priority, including when the user selects our shared Stone asset. Existing observer hooks become inactive. UV-only redraws still restore the prior atlas correctly. Profiles/backups retain this per-unit setting.

See [setup instructions](SETTINGS.md). SharedMedia support gives ElvUI access to the material, not support for its full ornamental shells.

## Inset edges and independent shell fitting

All 42 identities use narrow crops of their own painted rails for an inner lip on health and power, plus soft inner shadows. The large shell remains behind native content; only the small edge strips use a separate mouse-transparent frame just above the owning StatusBar. No center-covering texture is created. Default edge depth is 1.5 UI units, capped at 10% of each bar's height so thin power bars remain readable. Set `unitFrameInset=0` to remove the inner edges. Explicit strata/level overrides also apply to the rim.

`unitFrameWidth` and `unitFrameHeight` are per-unit percentages (75–150, default 100). Width scales the complete artwork around the horizontal bar center; height scales both halves around one shared health/power-stack center, retaining their joined separator. These controls change only artwork dimensions and do not resize the native bars or portraits. The existing provider fitting still reserves source-proportional separator space. Reset unit-frame fitting restores only these two percentages and edge depth. Values are included in backups and edits wait until combat ends. Rim frames/textures are reused, hide with native bars and shell toggles, and defer protected visibility changes before retiring their records.
